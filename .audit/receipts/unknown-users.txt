## Root cause

1. Message load used `channel.fetchMessages()` (Solid uses `fetchMessagesWithUsers`), so authors not already in Ready never hydrated into `client.users` → snapshot fell back to Unknown / short id.
2. Mention chips only looked at `usersByIdFromMessages` (authors already in the list), so `@<id>` for members who had not spoken stayed `@Unknown user`.
3. System `systemNames` could bake short ids and then block the shared member map.

## How names resolve now

Shared path (member-list sibling):
- `displayNameForUser` — nickname → display name → username → short id
- `useChannelMembers` / `namesById` — `server.syncMembers` → plain member snapshots

Wired into chat:
- Authors: `fetchMessagesWithUsers` + `resolveMessageAuthorName` / `displayNameFromSdk`; render uses `displayedAuthorName` with `namesById` when the snapshot is still unresolved
- Mentions: `ChatPane` passes `namesById` into `MessageList` → `mergeUserNameLookups(namesById, usersByIdFromMessages(messages))` → `resolveUserMention`
- System lines: snapshot omits unresolved `systemNames`; MessageList `resolveSystemName` prefers resolved snapshot then `namesById` then short id
- Member list: same `useChannelMembers` cache (no second loader)
